# Handoff: `deepseek-harness-web`

## Scope and constraints

`$REPO/deepseek-harness-web/` is the canonical standalone Web prototype. The parent DeepSeek Harness repository is reference-only for this task: do not modify, delete, or rename pre-existing files outside this directory. Do not use `playwright-cli`. Do not send model requests without explicit authorization.

Read `README.md`, `package.json`, `cordis.yml`, `bin.mjs`, `check.mjs`, and `agent-presets/` before changing the prototype. Keep the README and this handoff synchronized with behavior.

## Current composition

`dsh-lan.pm2.config.cjs` provides a packaged PM2 launch definition for `bin.mjs`, fixed to port 3081 on `0.0.0.0` with authenticated remote settings enabled. Its explicit `cwd` keeps relative runtime paths anchored to the installation directory even when PM2 is invoked elsewhere.

The distribution keeps the Web UI roster, host RPC, local Bash/PowerShell/filesystem execution, jobs, skills, subagents, workflows, Code Mode, Cordis Mode, persistent terminals, and the `standard`, `code`, `minimal`, and `cordis` presets. The restored official `minimal` preset has a complete fixed persona and exposes only persistent Bash plus `str_replace_editor`. Session-content search is enabled through the existing in-memory `@deepseek-ai/dsh-session-query-sqlite` index with `openAt: first-search`, so SQLite import and JSONL reconciliation remain deferred until the first query. It uses published `0.1.0-rc.6` Harness packages and remains outside the parent pnpm workspace. Model-facing Web search/fetch is absent: the host web/search providers, every preset tool row, and their production dependencies were removed. The launcher defaults `NODE_USE_ENV_PROXY` to `1` by starting the actual service in one child process, so every native-fetch model request and discovery call honors `HTTP_PROXY`, `HTTPS_PROXY`, and `NO_PROXY`; an explicitly supplied value, including `0`, is preserved. Native environment-proxy support raises the declared Node 22 floor from 22.19 to 22.21 while Node 24 remains supported from 24.0.

`llm-custom-providers.mjs` replaces `@deepseek-ai/dsh-llm-pi-ai` while retaining the `llm-pi-ai` settings namespace required by the existing Models UI. It serves only explicitly declared custom routes using `openai-completions`, `openai-responses`, or `anthropic-messages`; OpenAI and Anthropic SDKs provide the wire clients. There are no official provider/model catalogs, OAuth flows, or ambient provider authentication. A dormant `custom-provider` directory template exposes the namespace to the Web custom-provider form but registers no model route. Profiles require `api`, `baseURL`, and at least one model. Schema-normalized empty `reasoningEfforts` maps are treated as unspecified; rejecting them previously prevented every ordinary configured profile from registering its settings namespace and left both Models-page add flows inert. OpenAI protocols support `/models` discovery; Anthropic models are entered manually. Existing durable message content remains usable, while pi-ai-private replay state is ignored.

The composition excludes session OpenTelemetry and the local sandbox stack. It restores `dsh-subprocess-local`, `dsh-terminal`, `dsh-terminal-bash`, `dsh-tool-bash-persistent`, and `node-pty`; commands and terminals therefore run directly under the host user's authority and the danger-full-access policy. The README Mermaid diagram covers the host, agent, PTY/local-execution, profile-overlay, and removed production components.

`profile-config.mjs` optionally consumes both monorepo-local bundles and an existing `$DSH_HOME/profiles/web` without replacing the standalone composition. `start.sh` and `start_lan.sh` set `DSH_LOCAL_PLUGINS_DIR=..`; startup scans that directory for package manifests declaring `dsh.bundle`, requires their published `main` artifact to exist, loads their patches in deterministic directory order, and bridges each package into the standalone installation's `node_modules` so Host resolution and `dsh-client-modules` browser discovery both retain the package name. Missing local build output fails with an `npm run bootstrap` hint. A same-named profile bundle is skipped in favor of the local checkout. Profile loading still filters `@deepseek-ai/dsh-base` and `@deepseek-ai/dsh-web-app`, applies every other bundle after local bundles, then applies the profile's `cordis.patch.yml`. Duplicate user-layer inserts are keyed by `id`: exact rows disappear, same-name rows become full overrides, and a different plugin name fails loud. A dangling bridge from a removed or changed source is replaced on the next load. Missing profiles remain a no-op. Loading is startup-only: the home-level `cordis.patch.yml` and live profile patch watching remain outside this standalone launcher. External host plugins are trusted code; `dsh-web-terminal` reaches the restored PTY subprocess implementation and can open an interactive terminal. The local `dsh-chat-process-visibility` Session Header switch persists a browser-wide preference and hides Chat tool, reasoning, injected-context, compaction/retry, and workflow-run process nodes without changing logs, execution, ordinary prose/status/error rows, or the separate trajectory view.

`web-startup.mjs` replaces the published Web startup provider so `--host 0.0.0.0` reaches the already network-capable Web Server. Loopback remains the default. Arbitrary syntactically valid DNS authorities now enter the authenticated path without a Host allowlist; `--trusted-host` remains backward-compatible for already-declared authorities, but is not a requirement. `--allow-remote-settings` opts authenticated same-origin LAN clients into the settings/credentials/model-discovery plane through `lan-settings.mjs`; it leaves native path actions and preset authoring loopback-only. Without the flag, the published connection plugin's original 403 remains.

`lan-auth/` adds the single-user authentication boundary requested for LAN serving. A request bypasses login only when both its socket peer and Host authority are loopback; LAN IPs, arbitrary DNS names, and locally proxied non-loopback authorities require a password. The plugin guards already-registered and future exact/prefix/fallback/upgrade handlers, so the SPA, plugin bundles, HTTP RPCs, and WebSockets share one check. Its two fixed `/auth/*` routes require a valid Host authority, same-origin Origin when present, and reject cross-site Fetch Metadata. After authentication, undeclared DNS authorities are forwarded internally through the reserved `dsh-auth.invalid` authority already trusted by the published connection layer; this removes the user-facing domain allowlist without accidentally opening methods that remain loopback-only. The authenticated `/web-terminal` upgrade is the exception: it keeps the original authority because that plugin applies its own same-origin/local-address fence, and replacing a Tailscale `100.64.0.0/10` Host with the internal bridge name would make it reject an already authenticated request. The password is the owner-only credentials reference `DSH_LAN_PASSWORD`, configured from the General settings row or the launch environment; no read response contains its value. An unconfigured password fails non-loopback access closed. Successful logins receive a random 7-day HttpOnly, SameSite=Strict in-memory session, limited to 16 live sessions; five failures per peer per minute are rate-limited. Password changes and process restarts invalidate sessions. This remains plain-HTTP authentication rather than transport security: the README still requires TLS, front-door controls, and firewall rules for Internet-facing deployments.

`web-crypto-polyfill.mjs` installs an index tap before the client module scripts. On plain-HTTP LAN origins where browsers omit the secure-context-only `crypto.randomUUID()`, it supplies RFC 4122 v4 IDs from `crypto.getRandomValues()`; native implementations remain untouched and no `Math.random()` fallback exists. This restores Host RPCs such as browse-directory listing but does not add TLS or other secure-context browser capabilities.

`web-mobile-style.mjs` adds deployment-owned responsive CSS and a small click behavior through the Web Server index tap without forking the published frontend. At widths up to 720px, and on short coarse-pointer landscape viewports, the collapsed sidebar rail becomes a full-width top toolbar while an explicitly expanded sidebar takes the full frame; selecting a session or search result from that expanded sidebar schedules the existing toggle control and returns to the conversation automatically. Conversation spacing and composer controls tighten, and the settings dialog becomes a full-height column with a horizontally scrollable section strip and non-zooming form controls. Semantic data/role/slot selectors cover the shell, session selection, and settings layout, while the few layout, conversation, workspace, and model-form overrides intentionally target the pinned rc.6 CSS-module classes and must be refreshed with a Harness package upgrade. This is baseline chat/settings support, not a complete mobile redesign of details, trajectory tables, or third-party client plugins. `README.md` shows the shipped 390×844 chat/top-toolbar and settings views from `design/mobile-chat.png` and `design/mobile-settings.png`; both images are included in the npm package.

`startup-diagnostics.mjs` expands startup failures recursively instead of printing only the outer Cordis stack. In particular, multi-entry Loader failures now list every `AggregateError` member and nested cause, so cross-server native dependency, missing package, profile bundle, permission, and configuration failures identify the actual entry and bottom-level error. The README warns not to copy `node_modules` across OS/CPU/libc boundaries and documents a clean target-host `npm ci --omit=dev` recovery path.

The official `@deepseek-ai/dsh-subprocess-local` is again the single `ctx.subprocess` provider. It supplies ordinary process collection/spill, cancellation, whole-tree termination, synchronous host-exit cleanup, and `node-pty` terminal allocation with foreground inspection/signalling and awaited session cleanup. Its consumers are local Bash/PowerShell, filesystem search, shell-backed background jobs, the Web terminal plugin, and the `minimal` preset's persistent Bash stack. The former custom non-PTY `local-subprocess.mjs` was deleted rather than retained as dead code.

## Remaining size choices

The provider scope is now limited. Removing the OpenAI and Anthropic SDKs would save more space but would transfer three streaming protocol implementations into this repository; do not replace them with hand-written transports without a measured requirement.

The restored `node-pty` package ships roughly 58 MiB of multi-platform prebuilds. Recovering most of that cost requires platform-specific packaging; do not hand-maintain a PTY implementation or delete installed package files in ordinary npm installs.

An unpacked runtime below 100 MiB also requires reducing image/Sharp and Shiki assets. Keep compressed transfer size and installed size as separate measurements.

## Validation procedure for later changes

Use the smallest non-browser checks:

1. Run `npm run check` in a fresh production installation copied to an OS temporary directory.
2. Run `npm ls --omit=dev --depth=0` and assert removed packages are absent from the full closure.
3. Start with an isolated `DSH_HOME`, verify loopback HTTP 200, and call loopback-keyless `host.describe`, `llm.models`, `settings.describe`, and relevant roster RPCs.
4. Measure unpacked and compressed size.
5. On an all-interfaces isolated-home startup, verify loopback bypass, unconfigured LAN denial, arbitrary undeclared-domain login without `--trusted-host`, authenticated HTTP/WebSocket access, loopback-only RPC retention, password configuration from General settings, and session invalidation after password rotation.
6. Confirm `git status` reports only the `deepseek-harness-web/` tree and no pre-existing repository file changes.
